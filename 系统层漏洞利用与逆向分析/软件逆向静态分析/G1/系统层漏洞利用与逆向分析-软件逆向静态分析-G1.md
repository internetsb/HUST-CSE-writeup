将 `challenge.elf` 导入 Ghidra 并完成自动分析。首先定位程序入口点 `entry`（地址 `0x4017e0`），反编译后可以看到它调用了 `__libc_start_main`，其第一个参数 `FUN_00401905` 即为 `main` 函数。

将伪代码中的函数和变量还原为人类易读的形式。`FUN_0041bb60` 结合参数 `2`（stderr 的文件描述符）和字符串参数，可识别为 `fprintf(stderr, ...)`，即向标准错误输出提示信息。`FUN_00404e40` 接收缓冲区、最大长度 `0x40` 和一个流指针，对应 `fgets(buf, 64, stdin)`。`thunk_FUN_004127e0` 接收字符串和一个字符集参数（`DAT_004801f0` 指向换行符相关数据），功能为定位换行符位置，对应 `strcspn(buf, "\n")`，随后将该位置置零以去除尾部换行。`thunk_FUN_00412800` 为 `strlen`，计算输入长度。`FUN_004051d0` 为 `puts`，用于输出结果字符串。`FUN_0041bc30` 为栈保护失败处理函数 `__stack_chk_fail`。还原后的代码如下：

```c
int main(void) {
    char input[72];

    fprintf(stderr, "Enter the flag: ");
    if (fgets(input, 64, stdin) == NULL)
        return 1;

    input[strcspn(input, "\n")] = '\0';

    if (strlen(input) == 42) {
        for (int i = 0; i < 42; i++) {
            if ((input[i] ^ 0xAA) != encrypted_flag[i]) {
                puts("Wrong!");
                return 1;
            }
        }
        puts("Correct!");
        return 0;
    } else {
        puts("Wrong!");
        return 1;
    }
}
```

至此程序逻辑完全清晰：程序读取用户输入，去除换行符后检查长度是否恰好为 42 字节，然后将输入的每个字节与 `0xAA` 进行异或运算，逐一与存储在地址 `0x481140` 处的 42 字节密文进行比较，全部匹配则输出 `"Correct!"`。

通过 Ghidra 读取 `0x481140` 处的 42 字节数据为：`cc c6 cb cd d1 9d cf 99 cb 93 cc 98 c9 87 c8 92 9e 9b 87 9e ce 9c 9d 87 cb 9a cf 9f 87 9b cc 9c c9 92 c8 99 93 9a ce 98 9e d7`。

![image.png](https://k13in-images.oss-cn-wuhan-lr.aliyuncs.com/20260824151158388.png)

由于异或运算的自逆性质，将每个密文字节与 `0xAA` 异或即可还原明文 flag。编写 Python 解题脚本 ：

```python
data = [
    0xcc, 0xc6, 0xcb, 0xcd, 0xd1, 0x9d, 0xcf, 0x99,
    0xcb, 0x93, 0xcc, 0x98, 0xc9, 0x87, 0xc8, 0x92,
    0x9e, 0x9b, 0x87, 0x9e, 0xce, 0x9c, 0x9d, 0x87,
    0xcb, 0x9a, 0xcf, 0x9f, 0x87, 0x9b, 0xcc, 0x9c,
    0xc9, 0x92, 0xc8, 0x99, 0x93, 0x9a, 0xce, 0x98,
    0x9e, 0xd7
]

flag = ''.join(chr(b ^ 0xAA) for b in data)
print(flag)
```
